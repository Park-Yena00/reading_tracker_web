# 월별 통계: 방치한 책 순위 산정 로직 개선 보고서

## 1. 문제 상황 및 개요
홈 화면의 월별 통계인 **"최장기간 동안 안 읽은 (방치한) 책 BEST 3"** 기능에서, 실제 사용자의 독서 이력(DB 레코드)과 화면에 표시되는 순위가 일치하지 않는 현상이 발견되었습니다.

### 1.1 발견된 주요 이슈
- **완독 도서 포함**: 이미 다 읽은 책(`Finished` 상태)임에도 불구하고 활동일이 오래되었다는 이유로 방치 도서 목록에 포함됨.
- **데이터 필드 매핑 오류**: 서버에서 반환하는 최근 활동 도서 정보(`BookResponse`)의 ID 필드명과 프론트엔드에서 참조하는 필드명이 불일치하여 통계 집계에서 누락됨.
- **순위 산정 불일치**: 사용자의 DB 분석 결과(`book_id=18`이 가장 오래된 메모를 보유)와 시스템의 계산 결과가 상이함.

## 2. 원인 분석

### 2.1 로직 구현 미흡 (`js/utils/statistics-helper.js`)
기존의 `getNeglectedBooks` 메서드에서 1순위 그룹(독서 활동 이력이 있는 도서)을 추출할 때, 해당 도서의 카테고리 상태를 체크하지 않았습니다. 이로 인해 '방치'가 아닌 '완독' 상태의 책들이 순위에 진입하는 논리적 모순이 발생했습니다.

### 2.2 API 응답 구조 이해 부족
`memoService.getRecentMemoBooks` API가 반환하는 `BookResponse` 객체는 식별자로 `id` 필드를 사용하지만, 초기 코드는 `userBookId` 필드만을 조회하여 활동 이력 매핑(`activityMap`)이 정상적으로 이루어지지 않았습니다.

## 3. 개선 내용

### 3.1 완독 도서 제외 조건 강화
방치 도서의 정의는 "읽기 시작했으나 마무리를 짓지 않고 방치된 도서"이므로, 1순위와 2순위 그룹 모두에서 `Finished` 카테고리를 엄격하게 필터링하도록 수정했습니다.

```javascript
// 1순위: 활동 이력 있는 책 필터링 (완독 제외 조건 추가)
const booksWithActivity = allBooks
  .filter(b => activityMap.has(String(b.userBookId)) && b.category !== 'Finished')
  // ... 생략
```

### 3.2 데이터 프로퍼티 접근 정규화
서버 응답과 로컬 데이터 구조의 차이를 흡수하기 위해 식별자 및 시간 필드 접근 로직을 보완했습니다.

- **ID 참조**: `item.id || item.userBookId || item.bookId` 순서로 유연하게 조회
- **시간 참조**: `item.lastMemoTime || item.updatedAt` 순서로 최종 활동 시간 확보

### 3.3 설계 문서(`HOME_DASHBOARD_STATISTICS.md`) 동기화
설계 문서 3.2절에 명시된 "제외 대상" 및 "순위 산정 지표"를 코드에 정확히 반영하여, DB의 실제 메모 생성 시간 차이가 순위에 즉각 반영되도록 정렬 로직을 조정했습니다.

## 4. 결과 및 기대 효과
- **데이터 정확도 향상**: `book_id=18`과 같이 실제 방치 기간이 가장 긴 도서가 정확히 TOP 1으로 선출됩니다.
- **사용자 경험 개선**: 이미 완독한 책이 방치 목록에 뜨는 혼란을 방지하고, 다시 읽어야 할 책을 정확히 상기시켜 줍니다.
- **코드 견고성**: 다양한 API 응답 구조에도 유연하게 대응하는 헬퍼 함수를 구축했습니다.
